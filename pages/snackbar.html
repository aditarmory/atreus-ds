Snackbar

Snackbars provide brief, non-intrusive feedback about an operation. They appear temporarily at the bottom of the screen and disappear automatically. They can include a single optional action — never used for critical or persistent information.

A single container with a message label, semantic icon, optional action link, and optional close icon. All snackbars sit at the bottom of the viewport with 16px horizontal margin and a 20px border radius. Type communicates severity — Default for neutral, Success/Error/Warning/Info for semantic feedback.

When to use which type
✅ Use this type When… Example
Default Neutral confirmation, no semantic urgency. Outcome is expected and non-critical. "Changes saved", "Item deleted"
Success A key user action completed successfully. Reassures the user the task is done. "Transfer completed", "KYC verified"
Error A recoverable failure occurred. User may need to retry or take action — but it's not critical enough for a Dialog. "Payment failed. Try again.", "Upload error"
Warning A condition requires attention but hasn't failed yet. User should act soon. "Session expires in 5 min", "Low balance"
Info Contextual information the user might want but doesn't need to act on immediately. "Scheduled maintenance tonight", "New feature available"
Usage Guidelines
💬
Keep messages concise

1–2 lines maximum. If more explanation is needed, use a Dialog or inline error message instead.

⚡
One action maximum

Only one brief action is allowed — "Undo", "View", "Retry". Two actions is a signal you need a Dialog.

📍
Fixed bottom positioning only

Always anchor at the bottom of the viewport with 16px margin. Never float at top or center.

⏱️
Auto-dismiss after 3 seconds

Default dismisses at 3000ms. If the content needs attention (Warning, Error), add a close icon for manual dismissal.

🚫
Never stack snackbars

Only one visible at a time. Dismiss the current one before triggering the next.

🔕
Not for critical errors

Snackbars are low-priority, non-blocking feedback. Use Dialog for required confirmations or errors the user must resolve.

Principles
🎯
Semantic over decoration

Type choice must match outcome severity — never use Success styling on a neutral message, or Warning just to add color. Color carries meaning in banking contexts.

⚡
Non-blocking by design

Snackbars should never interrupt user flow. If a user must read and respond before continuing, that's a Dialog — not a Snackbar.

⏱️
Timing as communication

Auto-dismiss speed communicates urgency. 3000ms is the default. Add a close icon — never extend the timer — when the message is important enough to persist.
