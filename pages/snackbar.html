Snackbar

Snackbars provide brief, non-intrusive feedback about an operation. They appear temporarily at the bottom of the screen and disappear automatically. They can include a single optional action — never used for critical or persistent information.

Usage Guidelines
💬
Keep messages concise

Snackbar messages should be 1–2 lines maximum. If the message requires more explanation, use a Dialog or Toast instead.

⚡
One action maximum

Snackbars support a single, brief action (e.g., "Undo", "View", "Retry"). Never add two actions — that signals a Dialog is needed.

📍
Fixed bottom positioning only

Always anchor snackbars to the bottom of the viewport with 16px margin. Never float them at the top or center of the screen.

⏱️
Auto-dismiss after 3 seconds

Default snackbars dismiss after 3000ms. If the content requires user attention (e.g., error state), include a close icon to allow manual dismissal.

🚫
Never stack snackbars

Only one snackbar should be visible at a time. If a new snackbar is triggered while one is visible, dismiss the current one before showing the next.

🔕
Not for critical errors

Snackbars are for low-priority, non-blocking feedback. For critical errors or required confirmations, use a Dialog or an inline error message.
